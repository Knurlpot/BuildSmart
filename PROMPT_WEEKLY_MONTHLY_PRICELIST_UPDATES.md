# Implementing Weekly/Monthly Pricelist Updates in BuildSmart

## Executive Summary

BuildSmart's current pricelist system is **incompatible with frequent (weekly/monthly) supplier price updates**. The database schema stores only quarter + year granularity, which breaks when:
- Two uploads happen in the same quarter (one gets silently skipped)
- Companies want to track price changes within a quarter
- Suppliers don't follow quarterly schedules

**Solution**: Migrate from quarter/year to a `effective_date` DATE field with corresponding UI/backend updates.

---

## Current Problem: The Quarter/Year Limitation

### 1. Database Schema Issue

**Current Structure** (`historical_price_record` table):
```sql
CREATE TABLE historical_price_record (
    historicalrec_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    item_code INT NOT NULL,
    supplier_id INT,
    price_source VARCHAR(20) NOT NULL,
    region VARCHAR(30),
    quarter VARCHAR(2) CHECK (quarter IN ('Q1', 'Q2', 'Q3', 'Q4')),  ← PROBLEM
    year SMALLINT CHECK (year >= 2000),                               ← PROBLEM
    price DECIMAL(12,2) NOT NULL,
    recorded_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_historical_price UNIQUE (item_code, supplier_id, price_source, quarter, year)
);
```

**The UNIQUE constraint problem**:
```
UNIQUE (item_code, supplier_id, price_source, quarter, year)
```

This means only **ONE price per item/supplier/source per quarter**.

### 2. Real-World Scenario

**January 2026 - Supplier "ABC Steel" updates pricelist twice:**

| Date | Action | Result |
|------|--------|--------|
| Jan 5 | Upload pricelist v1 (prices ₱500/unit) | → Q1 2026 stored ✓ |
| Jan 12 | Upload pricelist v2 (prices ₱480/unit) | → DUPLICATE REJECTED ✗ |
| User gets outdated prices for 7 days | | |

**Why rejected?**
- Backend deduplicates by: `(file_hash, company_id, quarter, year)`
- Or if bypassing dedup, UNIQUE constraint blocks the INSERT

### 3. Upload Form Issue

**Current Frontend** (backend/app/routers/pricelist.py):
```python
@router.post("/upload", response_model=UploadResponse)
async def upload_pricelist(
    file: UploadFile = File(...),
    source: str = Form(...),
    supplier_id: int | None = Form(None),
    company_id: int | None = Form(None),
    quarter: str | None = Form(None),        ← Only these options
    year: int | None = Form(None),           ← Limited granularity
    db: Session = Depends(get_db),
):
    default_quarter, default_year = _default_period()
    period_quarter, period_year = quarter or default_quarter, year or default_year  # Auto-defaults to current Q/year
```

**User Experience**:
- Upload form shows: `[Q1 ▼] [2026]` only
- Can't specify "January 12, 2026" as the effective date
- System auto-defaults to current quarter—no granular control

## Detailed Solution

### Phase 1: Database Migration

#### Step 1.1: Add `effective_date` Column (Non-Breaking)

```sql
-- 1. Add new column (backward compatible)
ALTER TABLE historical_price_record 
ADD COLUMN effective_date DATE;

-- 2. Populate with quarter-based dates (first day of quarter)
UPDATE historical_price_record
SET effective_date = 
  CASE 
    WHEN quarter = 'Q1' THEN DATE(year::text || '-01-01')
    WHEN quarter = 'Q2' THEN DATE(year::text || '-04-01')
    WHEN quarter = 'Q3' THEN DATE(year::text || '-07-01')
    WHEN quarter = 'Q4' THEN DATE(year::text || '-10-01')
  END
WHERE effective_date IS NULL;

-- 3. Make NOT NULL after data is populated
ALTER TABLE historical_price_record 
ALTER COLUMN effective_date SET NOT NULL,
ALTER COLUMN effective_date SET DEFAULT CURRENT_DATE;

-- 4. Drop old UNIQUE constraint
ALTER TABLE historical_price_record
DROP CONSTRAINT uq_historical_price;

-- 5. Add new UNIQUE constraint with effective_date
ALTER TABLE historical_price_record
ADD CONSTRAINT uq_historical_price UNIQUE (item_code, supplier_id, price_source, effective_date);
```

#### Step 1.2: Update Material Price Variance Table

```sql
-- Same approach for material_price_variance table

def _default_effective_date() -> date:
    """Default to today's date instead of quarter start"""
    return date.today()


@router.post("/upload", response_model=UploadResponse)
async def upload_pricelist(
    file: UploadFile = File(...),
    source: str = Form(...),
    supplier_id: int | None = Form(None),
    company_id: int | None = Form(None),
    effective_date: str | None = Form(None),  # NEW: Accept date string from form
    db: Session = Depends(get_db),
):
    """
    Upload a pricelist with a specific effective date.
    
    Args:
        effective_date: ISO format date string (YYYY-MM-DD).
                       If not provided, defaults to today.
    """
    suffix = Path(file.filename).suffix
    file_upload_token = str(uuid.uuid4())
    dest = UPLOAD_DIR / f"{file_upload_token}{suffix}"
    
    with dest.open("wb") as out:
        shutil.copyfileobj(file.file, out)
    
    # Parse effective date
    try:
        upload_effective_date = (
            datetime.fromisoformat(effective_date).date() 
            if effective_date 
            else _default_effective_date()
        )
    except ValueError:
        raise HTTPException(
            status_code=400,
            detail=f"Invalid date format: {effective_date}. Use YYYY-MM-DD"
        )
    
    file_hash = calculate_file_hash(dest)
    file_size = calculate_file_size(dest)
    
    # NEW DEDUPLICATION: Use effective_date instead of quarter/year
    if company_id is not None:
        existing_upload = db.execute(
            select(PriceListUpload)
            .where(
                PriceListUpload.company_id == company_id,
                PriceListUpload.file_hash == file_hash,
                PriceListUpload.effective_date == upload_effective_date,  # ← Changed
                PriceListUpload.supplier_id == supplier_id,
            )
            .order_by(PriceListUpload.upload_timestamp.desc())
        ).scalars().first()
        
        if existing_upload is not None and existing_upload.processing_status == "completed":
            return UploadResponse(
                message=f"Duplicate upload for {upload_effective_date} (same file, date, supplier)",
                upload_id=existing_upload.upload_id,
            )
    
    # Create new upload record with effective_date
    db_upload = PriceListUpload(
        company_id=company_id,
        file_hash=file_hash,
        file_size=file_size,
        effective_date=upload_effective_date,  # ← Store the date
        source=source,
        supplier_id=supplier_id,
        processing_status="pending",
        upload_timestamp=datetime.now(),
    )
    
    db.add(db_upload)
    db.flush()
    
    # Trigger normalization task with effective_date
    task = normalize_price_list.delay(
        upload_id=db_upload.upload_id,
        company_id=company_id,
        effective_date=upload_effective_date.isoformat(),  # ← Pass to task
    )
    
    db.commit()
    
    return UploadResponse(
        task_id=task.id,
        upload_id=db_upload.upload_id,
        message=f"Pricelist upload created for effective date: {upload_effective_date}",
    )
```

import { db } from '@/lib/db';

export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const supplierId = searchParams.get('supplier_id');
  const itemCode = searchParams.get('item_code');
  const limit = parseInt(searchParams.get('limit') || '100');

  // Query by effective_date instead of quarter/year
  const query = db.$queryRaw`
    SELECT 
      hpr.historicalrec_id,
      hpr.item_code,
      hpr.effective_date,
      hpr.recorded_at,
      hpr.price,
      i.item_name,
      i.brand,
      i.unit,
      s.supplier_name
    FROM historical_price_record hpr
    JOIN items i ON hpr.item_code = i.item_code
    LEFT JOIN suppliers s ON hpr.supplier_id = s.supplier_id
    WHERE 1=1
      ${supplierId ? db.$queryRaw`AND hpr.supplier_id = ${parseInt(supplierId)}` : db.$queryRaw``}
      ${itemCode ? db.$queryRaw`AND hpr.item_code = ${parseInt(itemCode)}` : db.$queryRaw``}
    ORDER BY hpr.effective_date DESC
    LIMIT ${limit}
  `;

  const results = await query;
  return Response.json(results);
}

// New endpoint: Show price timeline for an item/supplier
export async function GET(request: Request) {
  const { searchParams } = new URL(request.url);
  const itemCode = parseInt(searchParams.get('item_code') || '0');
  const supplierId = searchParams.get('supplier_id');

  // Timeline ordered by effective_date
  const timeline = db.$queryRaw`
    SELECT 
      effective_date,
      price,
      COUNT(*) as update_count
    FROM historical_price_record
    WHERE item_code = ${itemCode}
      ${supplierId ? db.$queryRaw`AND supplier_id = ${parseInt(supplierId)}` : db.$queryRaw``}
    GROUP BY effective_date, price
    ORDER BY effective_date DESC
  `;

  return Response.json(await timeline);
}

## Questions & Answers

**Q: Will this affect existing quotations?**
A: No. Quotations store a reference to a `historical_price_record` ID, not the period. Once effective_date is added, quotations can refresh to latest prices by effective_date.

**Q: What about government price ingestion (DPWH/PSA)?**
A: Update `government_price_ingestion.py` to pass quarterly effective_date (e.g., Q1 2026 → 2026-01-01). No UI changes needed for automated sources.

**Q: How do we handle timezone issues?**
A: Use DATE (not TIMESTAMP) to avoid timezone confusion. All dates are supplier's local date, not UTC.

**Q: Can a supplier have multiple prices on the same day?**
A: Not in the UNIQUE constraint. If needed (e.g., region-specific prices), add region to unique constraint: `UNIQUE (item_code, supplier_id, effective_date, region)`.

**Q: What about retroactive price updates?**
A: User can upload a pricelist dated in the past (e.g., "This supplier sent us an updated price list effective Jan 1, but we got it Jan 15"). The effective_date reflects the supplier's intent, recorded_at shows when BuildSmart imported it.
